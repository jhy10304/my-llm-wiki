01 / 核心價值與效率

為什麼比賽與實務都用 std::sort？

💡 白話生活比喻：整理 1,000 張考卷

自己寫的氣泡/選擇排序（O(N²)）就像一張一張從頭找最低分，1,000 張考卷要比較 100 萬次；
而 std::sort（O(N log N)）懂得「對半切開分頭整理」，同樣 1,000 張考卷只需約 10,000 次動作，速度相差 100 倍！

⚙️ 底層黑科技：Introsort（三合一混合排序）

1. QuickSort (主力)

平時速度最快，負責大範圍快速分割。

2. HeapSort (保底)

遞迴太深時自動切換，防止最壞情況退化。

3. InsertionSort (收尾)

資料量變小時直接插入，省去函式呼叫開銷。

02 / 基礎語法與區間觀念

怎麼呼叫？看懂「前閉後開」區間 [first, last)

💡 排隊點名比喻

sort(起點, 終點) 的規則是「包含起點，但不包含終點」。就像老師說：「從第 1 號排到第 6 號的前面一位」，實際上只會整理 1～5 號，第 6 號（end()）是站在隊伍尾巴後面的界線標誌。

傳統陣列 a[]（長度 N）

#include <algorithm>
int a[5] = {5, 2, 9, 1, 7};

// 傳入記憶體指標：起點 到 起點+N
sort(a, a + 5); 
// 結果：{1, 2, 5, 7, 9}

動態陣列 vector

#include <algorithm>
vector<int> v = {5, 2, 9, 1, 7};

// 由小到大
sort(v.begin(), v.end());
// 小技巧：反向迭代器直接由大到小！
sort(v.rbegin(), v.rend());
03 / 進階自訂規則

不想只排由小到大？教你寫裁判函式 cmp

💡 比賽裁判比喻：bool cmp(a, b)

每次抓兩位選手 a 和 b 來問裁判：「請問 a 應該排在 b 前面嗎？」
回傳 true = 是，a 排前面；回傳 false = 否，a 不排在前面。

寫法 1：獨立比較函式（雙條件）

// 先比 first 升序；若平手，比 second 降序
bool cmp(pair<int,int> a, pair<int,int> b) {
    if (a.first == b.first) 
        return a.second > b.second;
    return a.first < b.first;
}
sort(v.begin(), v.end(), cmp);

寫法 2：Lambda 匿名函式（現代推薦）

// 直接把規則寫在 sort 括號裡，免另外取名
sort(v.begin(), v.end(), [](int a, int b) {
    return a > b; // 由大到小
});
04 / 避坑指南與穩定排序

新手最常踩的三大地雷 & stable_sort

⚠️ 地雷 1：cmp 裡面寫 <= 或 >=

違反「嚴格弱序」原則！當兩人平手時若回傳 true，裁判會邏輯錯亂導致程式直接崩潰（Segfault）。
👉 鐵則：平手時必須回傳 false！

⚠️ 地雷 2：傳統陣列少加 1

長度為 N 的陣列若寫成 sort(a, a + N - 1)，最後一格永遠不會被排到。
👉 鐵則：一定要寫 sort(a, a + N)！

✅ 進階救援：分數相同想保留原本順序？用 std::stable_sort

std::sort 為了追求極致速度，相等元素的原本順序可能會被打亂。如果題目要求「分數相同時，先交卷（先輸入）的排前面」，只要把函式名稱改成 stable_sort(v.begin(), v.end(), cmp) 就能完美解決！
